# Emerald Group Bot 4.0.0

ربات فارسی مدیریت گروه تلگرام با سیستم XP و لول، فروشگاه اختصاصی هر گروه، کلکسیون محصولات، مأموریت‌های قابل تنظیم و پنل مدیریت توسعه‌یافته.

## قابلیت‌های نسخه 4.0.0

- بازطراحی منوی مدیریت گروه به بخش‌های اعضا، پیشرفت، اقتصاد، امنیت و گزارش‌ها.
- دستورهای مدیریتی گروه: بن، بن زمان‌دار، اخراج، رفع بن، سکوت زمان‌دار، رفع سکوت و اخطار.
- فقط مالک اصلی گروه (Creator) می‌تواند با `/modadd` و `/modremove` مدیران مجاز را تعیین کند؛ مدیران مجاز فقط دستورهای مدیریتی اعضا را اجرا می‌کنند.
- باشگاه بازی سبک با Mini App شامل مار، حافظه، دوز و سرعت واکنش؛ رکورد و XP بازی مستقل از XP اصلی گروه است.
- احراز هویت Mini App با HMAC تلگرام، نشست یک‌بارمصرف، محدودیت امتیاز، cooldown و سقف XP بازی روزانه.

## قابلیت‌های موجود
- تمام قابلیت‌های XP، لول‌بندی، مأموریت‌ها، دستاوردها، فروشگاه و پنل نسخه 2 حفظ شده‌اند.
- لایه مدیریت گروه با تفکیک مالک تلگرامی گروه، مالک سیستمی ربات و مدیران مجاز.
- ثبت اخطارها، پاک‌سازی اخطارها و ثبت سوابق عملیات مدیریتی در SQLite.
- دستورات بن، رفع بن، سکوت زمان‌دار، رفع سکوت و مدیریت فهرست مدیران مجاز.

## قابلیت‌های نسخه 2
- فروشگاه جداگانه برای هر گروه با محصولات لقب، نشان و قاب پروفایل.
- خرید امن XP با تراکنش دیتابیس؛ جلوگیری از خرید تکراری و خرید بدون موجودی کافی.
- کلکسیون هر عضو و امکان فعال‌سازی محصول خریداری‌شده در پروفایل.
- ثبت خرید و موجودی باقی‌مانده؛ داشبورد تعداد اعضا، مجموع XP، فعالیت اخیر و خریدها.
- لول‌بندی مستقل هر گروه با حالت آسان، استاندارد و سخت، به‌علاوه هزینه XP سفارشی برای لول‌های مشخص.
- مأموریت‌های XP روزانه، XP هفتگی و تعداد پیام روزانه؛ هدف و پاداش هرکدام از پنل قابل تنظیم است.
- مدیریت قیمت و فعال/غیرفعال‌کردن محصولات از پنل گروه.
- مهاجرت افزایشی SQLite؛ کد برای افزودن ستون‌ها و جدول‌های جدید طراحی شده و دیتابیس نمونه در این بسته قرار نگرفته است.

## پیش‌نیازها
- Python 3.10 یا جدیدتر
- بات تلگرام ساخته‌شده با BotFather
- اتصال پایدار سرور به Telegram Bot API

## نصب در لینوکس
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
nano .env
python bot.py
```

## نصب در ویندوز PowerShell
```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
python bot.py
```

اگر PowerShell جلوی فعال‌سازی محیط مجازی را گرفت، فقط برای پنجره فعلی:
```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
.\.venv\Scripts\Activate.ps1
```

## تنظیمات `.env`
- `BOT_TOKEN`: توکن بات از BotFather
- `OWNER_ID`: شناسه عددی تلگرام مدیر اصلی
- `DATABASE_PATH`: مسیر فایل SQLite؛ روی Railway باید مسیر Volume پایدار باشد، مانند `/data/group_bot.db`
- `XP_PER_MESSAGE`: مقدار پیش‌فرض XP هر پیام واجد شرایط
- `XP_COOLDOWN_SECONDS`: فاصله پیش‌فرض دریافت XP
- `ADMIN_LEVEL`: لول پیش‌فرض لازم برای درخواست ادمینی

تنظیم XP، سقف روزانه، حالت لول، هزینه لول‌های انتخابی، مأموریت‌ها و فروشگاه از پنل هر گروه مستقل است.

## راه‌اندازی بازی‌های داخل تلگرام

1. در Railway برای سرویس یک دامنه عمومی HTTPS فعال کن.
2. متغیر `MINI_APP_URL` را روی ریشه همان دامنه قرار بده؛ نمونه: `https://your-service.up.railway.app`.
3. در `@BotFather` از مسیر `/mybots` → انتخاب ربات → `Bot Settings` → `Configure Mini App`، Mini App را فعال کن و همان URL را به‌عنوان Main Mini App ثبت کن.
4. Deploy کن و در گروه دستور `/games` را بزن. لینک تولیدشده، شناسه گروه را با امضای HMAC حمل می‌کند تا رکوردها بین گروه‌ها قاطی نشوند.
5. برای پروفایل بازی از `/gameprofile` و برای جدول‌ها از `/gametop`، `/gametop snake`، `/gametop memory`، `/gametop tictactoe` یا `/gametop reaction` استفاده کن.

Mini App باید از طریق HTTPS عمومی باز شود. برنامه در کانتینر Railway روی `PORT` گوش می‌دهد و TLS را دامنه/پروکسی Railway ارائه می‌کند. هیچ Bot Token یا اعتبارنامه‌ای در HTML قرار نمی‌گیرد.

**ضدتقلب و اعتبارسنجی رکورد:** هویت کاربر با داده امضاشده تلگرام بررسی می‌شود؛ نشست‌ها یک‌بارمصرف و زمان‌دارند. برای مار، حافظه و دوز، سرور seed نشست را نگه می‌دارد و مسیر حرکات را دوباره اجرا و امتیاز را مستقلاً محاسبه می‌کند؛ در بازی واکنش نیز زمان شروع علامت و زمان لمس سمت سرور اندازه‌گیری می‌شود. محدودیت امتیاز، cooldown و سقف ۱۵۰ XP بازی در روز هم فعال است. هیچ سیستم کلاینتی در برابر اتوماسیون پیشرفته تضمین مطلق ندارد، اما امتیاز ارسالی خام به‌تنهایی پذیرفته نمی‌شود. XP بازی به XP اصلی گروه اضافه نمی‌شود.

## مدل دسترسی نسخه 4
- `OWNER_ID` مالک سیستمی ربات است و دسترسی پنل سراسری موجود را حفظ می‌کند؛ این شناسه به‌تنهایی مجوز بن/سکوت در گروه‌ها نیست.
- مالک تلگرامی گروه (Creator) مرجع اصلی مجوزهای مدیریتی همان گروه است و تنها او می‌تواند مدیر مجاز اضافه یا حذف کند.
- مدیران گروه می‌توانند درخواست‌های ادمینی را بررسی و رد کنند؛ تأیید نهایی و ارتقای واقعی عضو فقط با `OWNER_ID` انجام می‌شود.
- مدیران مجاز فقط دستورات مدیریتی گروه را اجرا می‌کنند؛ دسترسی آن‌ها برای هر گروه جداگانه در SQLite ذخیره می‌شود.
- برای اجرای بن/سکوت/رفع محدودیت، خود ربات باید مدیر گروه و دارای مجوز Restrict/Ban Users باشد.
- عملیات مدیریتی و اخطارها در دیتابیس ثبت می‌شوند.
- برای هدف‌گیری عضو، روی پیام او ریپلای کن یا شناسه عددی‌اش را وارد کن. شناسه کاربری به‌جای نام کاربری استفاده می‌شود.
- مدت سکوت با قالب `30s`، `3m`، `2h` یا `1d` تعیین می‌شود؛ حداقل ۳۰ ثانیه و حداکثر ۳۶۶ روز است.

**وضعیت بررسی نسخه 4.0.0:** ۱۸ آزمون خودکار موفق شده‌اند؛ فایل‌های Python از نظر Syntax و کد JavaScript بازی‌ها از نظر Syntax بررسی شده‌اند؛ مسیرهای `/health` و `/games` در سرور محلی پاسخ داده‌اند؛ مهاجرت آزمایشی از دیتابیس قدیمی نیز XP اعضا را حفظ کرده و `PRAGMA integrity_check` نتیجه `ok` داده است. اتصال زنده به گروه تلگرام و اجرای واقعی Mini App در کلاینت‌های موبایل هنوز انجام نشده است. برای همین ابتدا در محیط آزمایشی Deploy کن و بعد از تنظیم Main Mini App در BotFather، بازی‌ها و دستورات مدیریتی را در گروه آزمایشی بررسی کن.

## افزودن محصول از پنل
در `/admin` گروه را انتخاب کن، وارد «اقتصاد و فروشگاه» شو و سپس «مدیریت محصولات فروشگاه» را باز کن. افزودن محصول با قالب زیر است:

`نام محصول | نوع (لقب/نشان/قاب) | قیمت XP | قیمت امتیاز ویژه | ایموجی`

مثال: `لقب زمردی | لقب | 500 | 250 | 💚`
قیمت XP و امتیاز ویژه جداگانه قابل تنظیم هستند. قالب قدیمی چهارقسمتی هم برای قیمت یکسان پشتیبانی می‌شود.

نمونه: `لقب زمردی | لقب | 500 | 💚`

می‌توان قیمت را تغییر داد یا محصول را فعال/غیرفعال کرد. محصول غیرفعال برای خرید جدید نمایش داده نمی‌شود؛ خریدهای قبلی به‌عنوان مالکیت عضو باقی می‌مانند.

## سفارشی‌سازی لول
در تنظیمات گروه، «سیستم لول‌بندی» را باز کن و حالت آسان، استاندارد یا سخت را انتخاب کن. برای تعیین XP رسیدن به لول‌های خاص، «تعیین XP لول‌های مشخص» را بزن و مقادیر را به شکل `لول=XP` وارد کن؛ مثال:

`2=80 3=120 4=180 10=500`

عدد واردشده، XP لازم برای رسیدن از لول قبلی به همان لول است. فقط لول‌های واردشده سفارشی می‌شوند و بقیه از حالت انتخابی استفاده می‌کنند. پاک‌کردن این تنظیمات با نوشتن `پاک کردن` انجام می‌شود.

## نکات مهم انتشار و دیتابیس
1. قبل از انتشار هر نسخه، از فایل دیتابیس زنده بکاپ بگیر.
2. `data/group_bot.db` نمونه یا دیتابیس محلی را روی دیتابیس زنده کپی نکن.
3. روی Railway مقدار `DATABASE_PATH` را به مسیر Volume پایدار تنظیم کن و آن را به مسیر محلی تغییر نده.
4. ابتدا نسخه را روی شاخه/محیط آزمایشی تست کن؛ بعد از بررسی بکاپ و تست، نسخه زنده را به‌روزرسانی کن.
5. برای اجرای آزمون‌های محلی: `python -m unittest discover -s tests -v`. این آزمون‌ها جای تست زنده تلگرام و بررسی تعاملی UI را نمی‌گیرند.
6. برای اینکه بات پیام‌های عادی گروه را ببیند، در صورت نیاز `/setprivacy` را در BotFather خاموش کن و بات را دوباره به گروه اضافه کن.

## محدودیت‌های فعلی
- حالت لول شامل سه پیش‌تنظیم و هزینه‌های سفارشی برای لول‌های مشخص است؛ برای هر سطح می‌توان هزینه رسیدن را جدا تعیین کرد.
- مأموریت‌های فعلی شامل XP روزانه/هفتگی و تعداد پیام روزانه‌اند؛ سازنده آزاد برای مأموریت‌هایی مثل فعالیت در چند روز یا رسیدن به لول خاص، هنوز پیاده‌سازی نشده است.
- قاب پروفایل فعلاً به‌صورت یک آیتم نمایشی در پروفایل ثبت می‌شود؛ ظاهر واقعی پیام تلگرام قابل رنگ‌آمیزی نیست.
